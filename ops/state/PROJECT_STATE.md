## Open feedback & critiques

- OSWorld-Human has incomplete steps (e.g., type but never press Enter), causing Human Agent failures unrelated to model capability.
- Models race ahead while screen is still loading from the previous action.
- OSWorld initialization errors (e.g., Chrome not opened on environment setup) corrupt evaluation.
- Benchmark drift concern: websites/software drift over time, potentially invalidating trajectories and a proper OSWorld-Human release.
- Relevance concern: frontier models are now evaluated on OSWorld v2.0 — unclear if the benchmark remains meaningful for small-model error analysis.
- Historical screenshots can confuse models even when action history is included; unclear whether CUAs genuinely perform worse with screenshot context and why.
- Planning/reflection phases often take far more steps than necessary (easy: 3–4 steps, medium: 4–9, hard: 10+).
- Icon accuracy is the main differentiator across grounding benchmarks (21–72% range); text grounding is relatively saturated (70–82%).
- Post-training small models may be difficult because they are likely distillation-trained.
- Models are stateless across trajectories — a known failure mode in long-horizon tasks.
- SURA application did not go through; re-application needed.

**Release / datasets**
- Release a proper OSWorld-Human dataset with full trajectories *(blocked by benchmark drift concern — provisional)*.

**Grounding**
- Screenshot generation as grounding method — generate grounding labels with image diffusion (SD3); use an unusual visual marker (e.g., houndstooth pattern) not present in standard UIs but easy for diffusion models to produce; fall back to traditional CV for detecting markers.
- Orthogonal icon-meaning data sources — PowerPoint documentation, webpage alt-text, etc. to improve icon understanding.
- Adaptive test-time compute for small models — e.g., ReVL recursive grounding approach; test-time compute beyond chain-of-thought.
- Two-model separation of perception and planning — one model for candidate selection, one for action output; optional third model for tool calls (web search / documentation lookup).
- Special "call-another-model" action — main VLM delegates bounding-box/grounding reasoning to a specialized model.
- Novel dataset not in Qwen training data — to differentiate grounding results; explore synthetic data gen + data augmentation (paired screenshot + HTML). *(Amaad)*
- Process Reward Models for CUA — *Let's Verify Step by Step* applied to OSWorld-Verified. *(provisional)*

**Memory / observation**
- GUI-state memory compression — compress GUI state instead of passing raw screenshots; helps with sudden ads/pop-ups.
- Streaming visual observations — frame-difference summaries, learned temporal representations, or compressed memory instead of full screenshot history; relevant for scrolling, video watching, game playing, dynamic UIs; not solved even for frontier models.

**Planning / reasoning**
- World models for planning in CUA — allow world model to explore new software and generate its own training data.
- RL for best-action prediction — model predicts state after candidate actions, nudged toward best; supervise reasoning traces.
- Reward efficient thinking — incentivize shorter, more effective reasoning traces.
- Instruction enhancement via LLM — LLM takes original task instruction and adds broad directions + success metrics before passing to CUA.

**Training data**
- Training on YouTube computer-use tutorials — leverage video demonstrations (CUA-Suite already exists; also online-video inference paper); Gemma 4 trained on video.
- Agentic trajectory scraping from videos + synthetic augmentation — create new traces from video; open question: are models good enough to model computer environments?
- Synthetic RL environment task generation.

**Architecture / system**
- Pixel-only CUA with optional code/tool use — CodeAct-style tool use to compensate for small-model capacity (image cropping, change tracking, structured memory).
- Fully open-source CUA — use Molmo-class models (fully open weights + training provenance) to differentiate from QwenVL black-box baselines; enables studying how backbone VLM properties affect CUA performance.
- RL training for small VLM agents — after establishing imitation-learning baseline.
- Harness design as a research variable — iterating observe-plan-act loop, memory, retries, action abstraction, subgoals, self-checking; analogous to NAS.

**Later / exploratory**
- Auto-research agents — spin up agents to survey literature and brainstorm (Karpathy-style). *(P3/later)*
